<h1>🦁 MrBeast GTFO</h1>

<p><b>Тестовый кастомный бот для модерации Discord от мошеннических сообщений «Mr. Beast»</b></p>

<h2 align="center">О проекте</h2>

Бот определяет аккаунт, который за несколько секунд рассылает одни и те же картинки по разным каналам, отправляет его в таймаут, удаляет его сообщения и формирует отчёт. Проект изначально разработан под **Termux**: бот и веб-панель управления работают непосредственно на телефоне.

<h2 align="center">Возможности</h2>

- 🚨 Автоопределение: N изображений в M каналах за K секунд (по умолчанию 4 / 2 / 10)
- ⏱️ Таймаут нарушителю с пояснением в журнале аудита
- 🗑️ Удаление сообщений нарушителя за выбранный период во всех каналах
- 📋 Отчёты в канале логов и в веб-панели
- 🖥️ Тёмная веб-панель в стиле Discord: логи, статус, настройки серверов, языки
- 🔄 Обновление бота из панели одной кнопкой, без переустановки и без потери данных
- 🔐 Вход по паролю; токен, пароль, логи и изображения хранятся в защищённом виде
- 🔑 Сброс пароля через Discord (привязанный аккаунт администратора)
- 🧹 Удаление данных пользователя из логов по юзернейму или ID
- 🛰️ Прокси и подписки (VLESS, SOCKS5, HTTP и другие) на случай блокировки Discord
- 🌐 Русский и английский: язык бота и язык панели настраиваются отдельно

<h2 align="center">Установка на Termux</h2>

> Устанавливайте Termux из **F-Droid** или **GitHub**: версия из Google Play устарела.

Одна команда устанавливает все зависимости и сразу запускает бота:

```bash
pkg install -y git && git clone https://github.com/BigFloppa9/MrBeast-GTFO && cd MrBeast-GTFO && bash install.sh
```

Скрипт сам определяет, где запущен (Termux, Docker или обычный Linux-сервер), и устанавливает всё необходимое без вопросов.

После запуска в консоли отобразятся две ссылки:

```
http://192.168.x.x:8080   ← с любого устройства в вашей Wi-Fi сети
http://localhost:8080     ← с самого устройства, где запущен бот
```

Откройте любую из них и пройдите первичную настройку. Если порт 8080 занят, будет выбран следующий свободный; актуальный адрес всегда выводится в консоль.

**Повторный запуск** (после выключения телефона или закрытия Termux):

```bash
cd MrBeast-GTFO && bash start.sh
```

<details>
<summary><b>Повторная установка и удаление</b></summary>

<br>

Если установка уже выполнена и вы находитесь в папке `MrBeast-GTFO`, повторное выполнение установочной команды создаст папку внутри папки. Для удаления и переустановки используйте команды ниже.

**Удаление** (вместе со всеми данными: токен, настройки, логи):

```bash
cd ~ && rm -rf MrBeast-GTFO
```

**Переустановка с нуля** (данные будут удалены):

```bash
cd ~ && rm -rf MrBeast-GTFO && pkg install -y git && git clone https://github.com/BigFloppa9/MrBeast-GTFO && cd MrBeast-GTFO && bash install.sh
```

**Переустановка с сохранением данных:**

```bash
cd ~ && cp -r MrBeast-GTFO/data ~/mrbeast-data-backup && rm -rf MrBeast-GTFO && git clone https://github.com/BigFloppa9/MrBeast-GTFO && cp -r ~/mrbeast-data-backup MrBeast-GTFO/data && cd MrBeast-GTFO && bash install.sh
```

Для обычного обновления переустановка не требуется: используйте кнопку в панели (раздел «Настройки») либо команду `cd MrBeast-GTFO && git pull`.

</details>

<details>
<summary><b>Docker и другие серверы</b></summary>

<br>

Запустите `install.sh` внутри контейнера или на сервере так же, как в Termux. В Docker опубликуйте порт панели параметром `-p 8080:8080`. Порт, адрес и папку данных можно задать переменными окружения:

| Переменная | По умолчанию | Назначение |

| `MRBEAST_DATA_DIR` | `./data` | Папка с настройками, логами и ключами |

<h2 align="center">Создание бота в Discord</h2>

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications) и нажмите **New Application**.
2. Перейдите на вкладку **Bot** → **Reset Token** и скопируйте токен. Он потребуется при первой настройке панели. Не передавайте его третьим лицам.
3. Там же, в разделе **Privileged Gateway Intents**, включите:
   - **Server Members Intent**
   - **Message Content Intent**
4. Перейдите на вкладку **OAuth2 → URL Generator** и выберите:
   - **Scopes:** `bot` и `applications.commands`
   - **Bot Permissions** (минимально необходимые, **обязательные**):

   | Право (русский портал) | Право (английский портал) | Назначение |
   |---|---|---|
   | Просматривать каналы | View Channels | доступ к каналам |
   | Читать историю сообщений | Read Message History | поиск сообщений нарушителя |
   | Управлять сообщениями | Manage Messages | удаление сообщений нарушителя |
   | Управлять участниками | Moderate Members | выдача таймаута |
   | Отправлять сообщения | Send Messages | отчёты в канале логов |
   | Встраивать ссылки | Embed Links | отчёты отправляются как embed |
   | Банить участников | Ban Members | только для пресетов наказаний с баном |

5. Откройте сгенерированную ссылку внизу страницы и добавьте бота на свой сервер.

⚠️ **Роль бота должна быть выше ролей, которым он выдаёт таймаут** (Настройки сервера → Роли). Администраторам и владельцу сервера Discord таймаут выдать не позволяет.

<details>
<summary><b>Роль бота, цвет и закрытые каналы</b></summary>

<br>

Роль с именем бота Discord создаёт сам при добавлении, с правами из ссылки шага 4. Если права не были отмечены, роль получится пустой. Исправить можно так:

- сгенерировать ссылку заново с правами из таблицы и открыть её на своём сервере (права роли обновятся);
- либо вручную: **Настройки сервера → Роли →** роль с именем бота → включить права из таблицы.

Цвет роли в ссылке задать нельзя: откройте ту же роль и укажите **#8000FF** (RGB 128, 0, 255).

Каналы, которые не видят обычные пользователи (например, канал логов): у роли бота должно быть право **Просматривать каналы** на сервере, а если в самом канале права переопределены, добавьте туда роль бота с правами **Просматривать канал**, **Отправлять сообщения** и **Встраивать ссылки**. Чтобы бот сам получал доступ к каналу логов, можно выдать право **Управлять каналами** / Manage Channels (необязательно).

</details>

<h2 align="center">Первый запуск панели</h2>

1. Откройте ссылку, выведенную в консоль.
2. Вставьте **токен бота**, задайте **пароль панели** (не короче 8 символов) и выберите язык бота. Язык панели переключается кнопками EN / RU в левом верхнем углу.
3. Нажмите **«Сохранить и запустить бота»**. Токен проверяется в Discord перед сохранением. Если связаться с Discord не удалось (например, он недоступен у вашего провайдера), данные всё равно сохраняются, а проблема отображается в панели.

> Завершите настройку сразу после запуска: пока она не пройдена, владельцем панели становится первый, кто откроет ссылку. Панель работает по HTTP, используйте её только в доверенной сети.

<h3 align="center">Разделы панели</h3>

| Раздел | Содержимое |
|---|---|
| **Нарушители** | Последние записи в виде сообщений Discord: имя, юзернейм и ID нарушителя, текст триггера, ссылка на канал, изображения (одинаковые хранятся один раз), действие. Обновляются автоматически. На ПК лента устроена как в Discord: новые записи внизу, при открытии вкладки вы уже внизу, прокрутка вверх показывает более старые; на телефоне новые записи сверху |
| **Статус** | Пинг, аптайм, кнопки управления, адреса панели в сети, последние 20 строк консоли. Состояние бота показано цветной капсулой под его именем слева (зелёная: в сети, оранжевая: подключение, красная: пауза или остановлен) |
| **Серверы** | Список серверов и для каждого сервера: пресет наказания, шаги, причины, срок сброса обнаружений, канал логов, пороги автоопределения |
| **Прокси** | Форма добавления сверху. Одиночные прокси списком, подписки разворачиваются стрелкой (ссылка скрыта «спойлером»: нажатие показывает или прячет её, ПКМ копирует). У каждого сервера пинг в мс, описание от провайдера, ручная проверка пинга (значок спидометра, у подписки сразу для всех серверов), редактор. Неработающий сервер показывает обратный отсчёт до автоудаления |
| **Логи** | Консольный лог на всю страницу с экспортом |
| **Настройки** | Языки, привязка аккаунта администратора, замена токена, обновления, удаление данных пользователя |

Подробности по разделам раскрываются в блоках ниже.

В логах панели поля нарушителя, текст триггера и названия каналов ограничены 69 символами, чтобы спам не раздувал историю. Видео не сохраняются. Записи хранятся не дольше 30 дней (и не более 300 штук).

<details>
<summary><b>Управление ботом (пауза, перезагрузка, остановка)</b></summary>

<br>

Состояние бота показано цветной капсулой под его именем (в сети, подключение, пауза, остановлен). Кнопки на вкладке **Статус**: **Пауза / Включить**, **Перезагрузить** и **Остановить / Запустить**. Во время паузы бот не реагирует на спам картинками, а ручные команды работают; остановка полностью отключает бота от Discord, панель остаётся доступной. Выбранное состояние сохраняется после перезапуска.

</details>

<h3 align="center">Прокси (если Discord заблокирован)</h3>

Во вкладке **Прокси** помещается до 1000 записей: ссылки, конфиги и подписки вставляются в одно поле. Бот сам выбирает самую быструю запись, переключается при сбое, а если не работает ни одна, подключается напрямую. Запись считается рабочей, только если через неё доступен Discord.

Принимаются (по одной ссылке в строке, либо один или несколько конфигов подряд):

| Формат | Пример |
|---|---|
| SOCKS5 | `socks5://user:pass@host:1080` |
| HTTP | `http://host:3128` |
| VLESS (ссылка) | `vless://uuid@host:443?type=tcp&security=reality&pbk=…&sid=…&flow=xtls-rprx-vision#название` |
| Конфиг Xray / V2Ray (JSON) | полный конфиг из приложения, например экспорт из v2rayNG |
| VMess, Trojan, Shadowsocks | `vmess://…`, `trojan://…`, `ss://…` |
| Подписка | `https://провайдер/sub/…` (или `happ://add/…`, `v2raytun://import/…`, `clash://install-config?url=…`): бот скачивает список серверов, кнопка «Обновить» перечитывает его |

<details>
<summary><b>Как бот выбирает и чистит прокси</b></summary>

<br>

- При каждом подключении бот проверяет **все** записи, подключается к самой быстрой и повторяет выбор, если она перестала отвечать. Если пинг выбранной записи выше 1000 мс, бот ищет более быструю; если лучше нет, остаётся на самой быстрой из имеющихся.
- Если не работает ни одна запись, бот подключается **напрямую**.
- В фоне раз в 10 минут проверяются все записи, включая неиспользуемые. Если бот работает напрямую, а какая-то запись ожила, он сам переключается на неё.
- Запись, которая не отвечает суммарно сутки, удаляется из списка автоматически. Время считается только пока у устройства есть интернет: короткие обрывы сети и сон телефона не засчитываются. Такая запись показывает красную точку и обратный отсчёт до удаления.
- Добавление и обновление подписок бота не перезапускает: новые серверы проверяются в фоне, а переключение происходит только при нестабильности активного прокси. Нажатие на название сервера в списке переключает бота на него без перезапуска (если сервер не отвечает, переключения не будет).

</details>

<details>
<summary><b>Подписки, ссылки и шифрование</b></summary>

<br>

- **Форматы.** VLESS: транспорты `tcp`, `ws`, `grpc`, `httpupgrade`, `xhttp` и защита `none`, `tls`, `reality`. Из JSON-конфига берётся исходящий прокси (с тегом `proxy` либо первый подходящий), другие протоколы Xray в нём тоже работают. Принимаются конфиги sing-box (поле `outbounds`), несколько конфигов подряд и `tg://socks`. Записи подписки других типов (hysteria, tuic и т. п.) пропускаются, а Telegram MTProto (`tg://proxy`) Discord не передаёт и отклоняется.
- **Загрузка подписки.** Запрос идёт с несколькими User-Agent по очереди (Happ, v2rayN, браузер, curl), так как провайдеры отвечают клиентам по-разному. Если напрямую не вышло (таймаут, блокировка), панель пробует текущий прокси, затем до пяти самых быстрых рабочих. Так же скачиваются список ключей `happ://crypt5` и фоновая картинка.
- **Шифрованные ссылки.** `happ://crypt5/…` расшифровываются локально ключами из открытого списка (github.com/cylaro/happ-decrypt, скачивается один раз в `data/cache`); подписка никуда не отправляется. Старые `crypt`, `crypt2`–`crypt4` не поддерживаются. Расшифрованный адрес сохраняется как адрес подписки.
- **Обновление подписки** только добавляет новые серверы: уже имеющиеся (одинаковые по адресу, порту и ключам) не меняются, а убранные провайдером остаются в списке. Удалённый вручную сервер при обновлении не возвращается.
- **Описание сервера** из параметра `serverDescription` показывается серым текстом под названием.
- **Xray и хранение.** Для SOCKS5, VLESS и конфигов используется ядро **Xray**: при первом использовании оно загружается с GitHub (с проверкой контрольной суммы) в `data/bin/xray`; если GitHub недоступен, положите файл `xray` в эту папку вручную. Записи и ссылки подписок хранятся в `data/proxies.json` в зашифрованном виде.

</details>

<details>
<summary><b>Если подписка не скачивается с телефона</b></summary>

<br>

Например, если сервер подписки блокирует ваш IP. Выполните на компьютере (Windows, Linux или macOS, нужен Python 3):

```bash
python tools/subscription.py "https://провайдер/sub/…" -o servers.txt
```

Файл `servers.txt` содержит ссылки серверов: откройте его и вставьте содержимое в поле во вкладке «Прокси».

</details>

<details>
<summary><b>Обновление из панели</b></summary>

<br>

1. Откройте **Настройки → Обновления** и нажмите **«Проверить обновления»**.
2. Если доступна новая версия, отобразится список изменений. Введите пароль панели и нажмите **«Обновить сейчас»**.
3. Бот остановится, загрузит обновление, проверит зависимости и новые файлы, после чего запустится снова. Данные и настройки сохраняются. При сбое выполняется откат к предыдущей версии. После перезапуска потребуется заново войти в панель.

</details>

<details>
<summary><b>Удаление данных пользователя</b></summary>

<br>

В **Настройки → Удаление данных пользователя** введите юзернейм (не отображаемое имя) или ID. Панель покажет число найденных записей. После подтверждения имя, юзернейм и ID в этих записях заменяются на `null`, а сохранённые текст сообщения и изображения удаляются; счётчики обнаружений и строки консольного лога с этим пользователем тоже стираются. Запись с ID `null` считается удалённой; пользователь, у которого имя буквально «null», удалённым не считается. Бот дополнительно удаляет **собственные** лог-сообщения об этом пользователе в каналах логов всех серверов (по сохранённым ссылкам на сообщения и просмотром истории канала за 30 дней); чужие сообщения не затрагиваются. Если бот не в сети, каналы Discord не проверяются.

</details>

<details>
<summary><b>Наказания, пресеты и счётчики</b></summary>

<br>

Во вкладке **Серверы** для каждого сервера выбирается пресет:

| Пресет | Что делает |
|---|---|
| Одно действие | таймаут и удаление сообщений с заданными значениями при каждом обнаружении |
| 4 обнаружения с последующей блокировкой | 1-е обнаружение: таймаут 5 мин и удаление за час; 2-е: сутки и сутки; 3-е: неделя и сутки; 4-е и далее: бан и удаление за сутки. К причине добавляется номер обнаружения и просьба связаться с модератором при ошибке |
| Бан при первом обнаружении | бан и удаление сообщений за сутки |
| Свой | до 8 шагов: действие (таймаут или бан), длительность, период удаления и причина для каждого |

Счётчик обнаружений ведётся отдельно для каждого пользователя на каждом сервере и сбрасывается после заданного числа дней без нарушений (по умолчанию 30, не больше 30). Дольше 30 дней ничего не хранится. Причина записывается в журнал аудита; отправка её нарушителю в личные сообщения по умолчанию выключена и включается галочкой в настройках сервера. При бане Discord удаляет сообщения за выбранный период (максимум 7 дней).

</details>

<details>
<summary><b>Перенос настроек, консольный лог, обновления</b></summary>

<br>

- **Настройки → Перенос настроек**: слева «Импорт», справа «Экспорт». Экспорт спрашивает пароль и сохраняет файл с настройками серверов, пресетами, причинами, счётчиками и прокси (подписки вместе с их серверами, в том виде, как они сейчас в списке); ID пользователей и данные прокси шифруются этим паролем, нарушители и логи не включаются. Импорт открывает выбор файла, проверяет его и спрашивает пароль; записи старше 30 дней отбрасываются.
- Вкладка **Логи** (между «Прокси» и «Настройки») показывает консольный лог на всю страницу, последние 300 строк с автообновлением; экспорт в txt, json или csv, за всё сохранённое время или с последнего запуска бота. Третий список фильтрует события: «Все», «Действия» (обнаружения и блокировки) и «Ошибки» (сбои и предупреждения); фильтр действует и на экран, и на экспорт. Файл `data/console.log` хранит до 2000 строк за 30 дней.
- Блок версии справа вверху **Настроек**: «Показать изменения» раскрывает последние коммиты (нужна установка через git), «Проверить обновления» запускает обычную проверку.

Сообщения о перезапуске в консольном логе:

| Сообщение | Что произошло |
|---|---|
| `restarting` → `restarted` | бот перезапускается (из панели, после смены настроек или прокси) |
| `network reconnect, restarting` → `restarted` | перезапуск из-за проблем с сетью |
| `reconnecting` → `reconnected` | активный прокси потерял связь, бот подключается заново |
| `proxy switched` | бот перешёл на другой прокси, не теряя связи |
| `reconnected (session resumed)` | Discord возобновил сессию после короткого обрыва |

Строка `[Tracker]` пишется после примерно 10 секунд тишины по пользователю и считает картинки по сообщениям: одно сообщение с 5 картинками даёт «5 images in 1 channel», а такое же сообщение в нескольких каналах подряд сводится в одну строку, например «4 images in 4 channels».

</details>

<details>
<summary><b>Привязка аккаунта и сброс пароля</b></summary>

<br>

Привязка необходима для восстановления пароля.

1. В панели откройте **Настройки → Аккаунты модераторов → Сгенерировать код**. Можно привязать до 10 аккаунтов, повторив шаги для каждого; отвязать аккаунт можно там же.
2. Отправьте боту в **ЛИЧНЫЕ** сообщения команду `/reg КОД`. Бот проверит, что вы администратор (или владелец) сервера, на котором он работает, и привяжет ваш аккаунт по ID.

Если пароль утерян:

1. На странице входа нажмите **«Забыли пароль?»**.
2. Отправьте боту в **ЛИЧНЫЕ** сообщения команду `/log` (без кода). Бот ответит кодом только привязанному аккаунту.
3. Введите код в браузере, затем дважды введите новый пароль.

Без привязанного аккаунта пароль можно вернуть **контрольными вопросами**: в **Настройки → Восстановление пароля** выберите до 3 вопросов (готовые или свой), ответы пишутся латиницей без пробелов (вместо пробела `_`) и хранятся только в виде хешей. Там же задаётся подсказка, которая показывается под полем пароля после двух неверных попыток. На странице входа при неверном пароле поле очищается.

Если не настроено ни привязки, ни вопросов, страница восстановления покажет команду переустановки бота для вашего устройства (Termux или другое). Переустановка удаляет все данные бота.

</details>

<h2 align="center">Хранение данных</h2>

Всё хранится в папке `data/` (в git не попадает). Токен, логи, изображения и список прокси шифруются (Fernet).

<details>
<summary><b>Файлы и что защищено</b></summary>

<br>

| Файл | Содержимое |
|---|---|
| `auth.json` | токен бота в зашифрованном виде и хэш пароля (PBKDF2-SHA256); сам пароль не хранится |
| `secret.key` | ключ шифрования |
| `settings.json` | настройки серверов |
| `config.json` | языки и привязанный аккаунт администратора |
| `proxies.json` | список прокси в зашифрованном виде |
| `bin/xray`, `xray/` | ядро Xray и его временный конфиг (появляются при использовании прокси) |
| `logs.json`, `images/` | логи (не дольше 30 дней, не более 300) и кэш изображений в зашифрованном виде |

Токен, логи и изображения шифруются (Fernet), ключ лежит отдельным файлом рядом, чтобы бот запускался самостоятельно после перезапуска. Это защищает от случайной утечки отдельного файла, но не от доступа ко всей папке `data/`. Не публикуйте её и не передавайте третьим лицам. Подробнее: [политика конфиденциальности](PRIVACY.md).

</details>

<h2 align="center">Рекомендации для Termux</h2>

- Отключите оптимизацию батареи для Termux, иначе Android может приостановить процесс.
- `start.sh` включает `termux-wake-lock`, чтобы устройство не усыпляло процесс. Уведомление Termux лучше не закрывать.
- Телефон и устройство, с которого открывается панель, должны находиться в одной сети.

<h2 align="center">Возможные проблемы</h2>

| Проблема | Решение |
|---|---|
| Панель сообщает, что Discord недоступен | Discord может быть заблокирован у провайдера: добавьте прокси во вкладке **Прокси** либо включите VPN на устройстве. Бот продолжит попытки подключения |
| «Discord отклонил токен» | Токен скопирован не полностью или был сброшен. Получите новый в Developer Portal и замените его в разделе «Настройки» |
| Панель сообщает о Intents | Включите **Server Members Intent** и **Message Content Intent**, затем перезапустите бота |
| Бот молчит в личных сообщениях | `/reg` и `/log` нужно выбрать из списка, который появляется после ввода `/`; обычный текст бот игнорирует и отвечает подсказкой. Если список пуст, перезапустите Discord |
| Слэш-команды не отображаются | Подождите несколько минут и перезапустите Discord. Бот должен быть добавлен со скоупом `applications.commands` |
| Панель не открывается с другого устройства | Консоль печатает все сетевые адреса телефона: используйте тот, что из вашей сети (обычно Wi-Fi). IP телефона можно сверить в роутере. Если не помогает, в роутере выключите «изоляцию клиентов» (AP isolation) и проверьте, что оба устройства в одной сети |
| Таймаут не выдаётся | Роль бота ниже роли пользователя, либо у пользователя права администратора |
| Нет отчёта в канале логов | Проверьте права бота в этом канале: View Channel, Send Messages, Embed Links |
