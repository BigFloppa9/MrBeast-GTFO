# HANDOFF: MrBeast GTFO (база знаний для продолжения в новом чате)

Версия кода: 2.5.1 (hotfix после 2.5.0, см. раздел 17). Репозиторий: https://github.com/BigFloppa9/MrBeast-GTFO (публичный, владелец BigFloppa9).

## 0. Как пользоваться этим файлом

Пользователь присылает в новый чат ссылку на репозиторий и этот файл, затем пишет список правок (например «1), 2), 3)»). Порядок работы:
1. Прочитать этот файл целиком. Открыть репозиторий через web_fetch (страница репо и нужные файлы) и сверить с разделом 3; если нужного файла не видно, попросить его прислать.
2. Если правка неоднозначна, задать вопросы **обычным текстом** до работы (не формами Q/A).
3. Править, тестировать (раздел 12), отдавать согласно разделу 1.
4. Не полагаться на память о прошлых чатах: всё важное здесь. Если в репозитории что-то отличается от файла, верить репозиторию и сказать об этом пользователю.

## 1. Пользователь и правила работы

- Русскоязычный студент, пишет неформально. Обращение: **Броня** (ранее Бронислава), женский род в русском (настройка стиля, не влияет на честность и качество).
- Точность важнее скорости. Нужен рабочий результат с первой-второй попытки. Файлы всегда отдавать, даже если ответ длинный.
- Код **без комментариев** (читать код пользователь не будет).
- Формат выдачи: по умолчанию **только изменённые файлы** (с указанием, куда какой положить); если просит, то **архив всего проекта + отдельно HANDOFF.md**. В последний раз просил именно архив проекта и этот md.
- Отладка: по одной команде, дождаться лога, без повторных объяснений.
- Не угадывать функции: если не уверена, спросить текстом.
- README в деловом стиле на «вы», заголовки и название по центру, нумерованные шаги, внизу только ник **BigFloppa9** (без «с помощью Claude»). Два файла: README.md (RU) и README_en.md (EN), образец оформления https://github.com/BigFloppa9/myinstants-mute-button
- Сокращать код по принципам ponytail (https://github.com/DietrichGebert/ponytail): минимум, переиспользование, stdlib и нативные возможности, но без урезания валидации, безопасности и обработки ошибок.
- Пользователь острый на лишние шаги и недосказанность; на раздражение отвечать спокойно и по делу. Чат у него может быть очень длинным (был 240k токенов), поэтому ответы писать компактно.
- Реальные серверы и ключи прокси, которые он присылает как тестовые, НЕ сохранять ни в репо, ни в тестах, ни в этом файле (использовать обезличенные).

## 2. Проект

Discord-бот против мошеннических сообщений «Mr. Beast»: аккаунт за секунды рассылает картинки (обычно 4+, часто текст «bro») по разным каналам. Бот определяет это, выдаёт таймаут, удаляет сообщения, пишет отчёт в канал логов и в веб-панель. Работает **на телефоне в Termux** (также Docker/Linux). Fly.io больше не используется (аккаунт удалён); файлы Fly (Procfile, Dockerfile, fly.toml, .github/workflows/deploy.yml) и старый bot.py должны быть удалены из репо (пользователь удаляет вручную).

Ситуация с Discord: у пользователя Discord без прокси недоступен; он ведёт бота через собственные прокси (VLESS). Для продакшен-приложения привилегированные интенты сняты (нужна верификация), поэтому сейчас он запускает временное приложение «Temp mrbeastgtfo» (интенты включены обычной галочкой). Запуск на Termux (Python 3.14) подтверждён логами: бот часами работал через локальный Xray.

## 4. Бот (mrbeast/bot.py)

- Intents: default + message_content + members. `commands.Bot` (prefix when_mentioned, tree_cls=GuardTree, proxy=...). Cog в setup_hook, один раз `tree.sync()`.
- Детекция (`Guard.on_message`): не-бот, сообщение на сервере, есть изображение (вложение image/* или embed image/thumbnail). Трекер (guild, user) за `auto_window_seconds`; срабатывает при `auto_min_images` картинок в `auto_min_channels` каналах (умолчание 4 / 2 / 10 с). `processed_users` в памяти. **При паузе (`config.bot_state == "paused"`) на серверах ничего не делает**; ручные команды работают.
- `run_auto`: таймаут → `capture_images` (до удаления; только вложения и доверенные embed discordapp.*, до 8 уникальных, 8 МБ, сигнатуры, SHA-256, через текущий прокси) → `purge_messages` → embed в канал логов (`build_embed`, текст до 900 символов) → `record_log` (панель).
- ЛС: любое обычное сообщение в ЛС получает подсказку «используйте слэш-команды» (раз в 30 с на пользователя): бот больше не молчит. В консоль пишется `[DM] ...` для /reg, /log и сообщений.
- Команды: `/mrbeast` (Moderate Members), `/mrbeastlog`, `/mrbeastconfig` (Administrator), все guild_only; `/reg code` и `/log` только в ЛС (allowed_contexts guilds=False, dms=True).
- `/reg`: проверка, что пользователь владелец или администратор на общем сервере (`is_admin_somewhere`, нужен members intent), затем одноразовый код из панели, привязка по ID.
- `/log`: только привязанному аккаунту и только если в панели нажато «Забыли пароль»; отвечает кодом (6 символов: A-Z a-z 0-9), его вводят в браузере.
- Причина таймаута: пусто = текст по умолчанию на языке бота (до 512 символов).

## 5. Веб-панель

Запуск `python -m mrbeast`. Порт `MRBEAST_PORT` (8080), перебор вверх до 100 попыток; хост `MRBEAST_HOST` (0.0.0.0); данные `MRBEAST_DATA_DIR`. Баннер печатает **все** сетевые адреса устройства (интерфейсы через ioctl SIOCGIFADDR, затем адреса маршрутов; порядок: Wi-Fi, прочее, мобильная сеть, VPN) с именем интерфейса и подсказкой про изоляцию клиентов; раз в 30 с проверяет смену адресов и печатает новый. Причина жалобы пользователя: старая версия печатала один адрес (192.168.1.212), а роутер выдал телефону 192.168.1.231.

Первичная настройка (`POST /api/setup`): токен + пароль (мин. 8) + повтор + язык бота (язык панели из переключателя EN/RU слева сверху). Токен проверяется у Discord; отклоняется только при 401, при недоступности Discord данные сохраняются (`warning`) и бот переподключается.

Безопасность: сессии в памяти (cookie `mb_session`, HttpOnly, SameSite=Strict, 12 ч; после перезапуска входить заново), проверка Origin и Content-Type=application/json для не-GET, CSP (script/style только свои; img-src: self, data, sun1-13.userapi.com для запасного фона kos), nosniff, лимиты попыток. PBKDF2-SHA256 400000 итераций. Смена токена и обновление требуют пароль. Смены пароля в настройках нет (только сброс).

Состояния бота `config.bot_state`: `running` / `paused` / `stopped` (сохраняются; при `stopped` бот не стартует при запуске, панель работает). API `POST /api/bot/{pause|resume|restart|stop|start}`.

API (кроме публичных требуют сессию):
- публичные: `GET /api/state`, `POST /api/setup`, `/api/login`, `/api/forgot/start|verify|finish`, `GET|HEAD /api/kos-bg`
- `POST /api/logout`, `GET /api/status` (бот, языки, модератор, код привязки, `network`, `bot_state`), `GET /api/logs?after=id`, `GET /api/image/{name}` (расшифровка на лету)
- `GET /api/img/bot`, `GET /api/img/guild/{gid}`: аватарки через **сервер** (скачивает с Discord через текущий прокси, кэш `data/cache`); клиент не ходит на CDN Discord, поэтому картинки грузятся и у устройств без VPN; при неудаче 404 и панель рисует кружок с буквой
- `GET|PUT /api/guilds/{gid}/settings`, `PUT /api/config`, `PUT /api/token`, `POST /api/moderator/code`
- `POST /api/privacy/erase {query, confirm}`
- `GET /api/update/check`, `POST /api/update/apply {password}`, `GET /api/update/status`
- `GET /api/proxy`, `POST /api/proxy {text}`, `DELETE /api/proxy/{id}`, `POST /api/proxy/sub {url}`, `POST /api/proxy/sub/{id}/update`, `DELETE /api/proxy/sub/{id}` (любое изменение перезапускает бота). С 2.4.0 `POST /api/proxy {text}` принимает и ссылки на подписки (строки https://… или с путём/query, обёртки happ://add/, v2raytun://import/, clash://install-config?url= и т. п.): `parse_input` возвращает записи, ошибки и список подписок; ответ содержит `errors[{code,n,detail}]`, в т.ч. `sub_truncated` при лимите 100

Интерфейс (vanilla JS, i18n в начале app.js): сверху панели всегда статус бота (в сети / пауза / остановлен ...), вкладки Логи (сообщения в стиле Discord), Статус (показатели, кнопки Пауза/Включить, Перезагрузить, Остановить/Запустить, адреса панели), Серверы (список серверов как выбор + настройки сервера), Прокси (с 2.4.0 отдельная вкладка между Серверы и Настройки: одно поле для ссылок, конфигов и подписок, список подписок, список записей, время последней проверки, отметка «нет интернета»), Настройки (языки, аккаунт модератора, токен, обновления, удаление данных). Логи: поля нарушителя, юзернейм, текст триггера, канал и сервер обрезаны до 69 символов; markdown триггера рендерится безопасно через DOM.

## 6. Данные и шифрование

- `auth.json`: `token_enc` (Fernet), соль/хэш пароля. `secret.key`: ключ Fernet (0600, каталог 0700), лежит рядом, чтобы бот стартовал сам: защита от утечки одного файла, не от доступа ко всей папке (честно написано в README и PRIVACY).
- `logs.json`, `images/*`, `proxies.json` шифруются тем же ключом. Логи: максимум 30 дней и 300 записей. `settings.json`, `config.json` открытым текстом.
- `LogStore.erase(query, apply)`: совпадение по ID или юзернейму (без регистра, без @); display/username/id становятся настоящим **null**; признак «стёрт» = `id is None` (пользователь с именем «null» стёртым не считается); у нарушителя также `trigger.text=null`, `trigger.images=[]`; копии в Discord-канале не трогаются.

## 7. Установка, запуск, обновление

- Termux: `pkg install -y git && git clone https://github.com/BigFloppa9/MrBeast-GTFO && cd MrBeast-GTFO && bash install.sh`. install.sh: определяет среду (termux/docker/linux), без вопросов (DEBIAN_FRONTEND=noninteractive, `--force-confdef --force-confold` = как Enter на конфиг-вопросы), на Termux ставит python-cryptography через pkg, discord.py через pip с `*_NO_EXTENSIONS=1`; пишет `.runtime`; **в конце сам запускает start.sh**. В сообщении путь печатается относительно домашней папки (`cd MrBeast-GTFO && bash start.sh`).
- Запуск после перезагрузки: `cd MrBeast-GTFO && bash start.sh` (включает termux-wake-lock).
- Переустановка/удаление: сворачиваемый блок в README (повторная установка внутри папки создаёт папку в папке).
- Обновление из панели (`updater.py`): fetch, сравнение с upstream, список коммитов; apply = остановка → `git pull --ff-only` → `pip install -r requirements.txt` (при externally-managed повтор с `--break-system-packages`) → проверка импорта в подпроцессе → `os.execv` на том же порту; при сбое откат `git reset --hard` и запуск бота. `data/` не затрагивается. Работает только для установок через git clone.
- Логи discord.py: фильтр `QuietReconnects` понижает «Attempting a reconnect» (обрыв шлюза через прокси, это нормально, сессия RESUME) до WARNING без трейсбека и скрывает asyncio «Unclosed connection».

## 8. Прокси (mrbeast/proxy.py)

Хранилище `data/proxies.json` (Fernet): `{"entries": [...], "subs": [...]}` (старый формат-список тоже читается). До 100 записей. Запись: `{id, type, label, ...}`; `http` хранит `url`, остальные (`socks5`, `vless`, `xray`) хранят `outbound` Xray; у записей подписки есть `sub` (id подписки); `down_since` ставится при первом провале.

Ввод (одна ссылка в строке либо JSON-конфиги подряд/массив): `socks5://[user:pass@]host:port`, `http://...`, `vless://uuid@host:port?...` (tcp/ws/grpc/httpupgrade/xhttp; none/tls/reality; flow, encryption в т.ч. mlkem, sni, fp, alpn, pbk, sid, spx, path, host, serviceName, mode, authority), полный конфиг Xray/V2Ray (берётся исходящий с тегом `proxy` или первый не freedom/blackhole/dns; inbounds/routing/dns/stats пользователя игнорируются), **подписка** (URL: загружается с UA `Happ/2.0.0`, сначала напрямую, затем через текущий прокси; тело base64/url-safe base64/текст ссылок/JSON; vmess/trojan/ss пропускаются и считаются; «Обновить» заменяет записи этой подписки).

Механика: `http://` идёт напрямую (параметр proxy у discord.py и aiohttp). Остальное через ядро **Xray**: локальный HTTP-вход 127.0.0.1:случайный порт, конфиг `data/xray/main.json`. Бинарник: `MRBEAST_XRAY`, `xray` из PATH, `data/bin/xray`, иначе автоскачивание GitHub Releases (`Xray-android-arm64-v8a.zip` на Termux arm64, иначе `Xray-linux-*`) с проверкой SHA2-256 из `.dgst`. В конфиг добавлены dns 1.1.1.1/8.8.8.8 и `sockopt.domainStrategy=UseIPv4` (на Termux нет /etc/resolv.conf).

Логика выбора (`ProxyPool`):
- `probe_all`: одним **вспомогательным процессом Xray** (`probe`, много входов/выходов) параллельно проверяет все записи запросом к `https://discord.com/api/v10/gateway` (таймаут 8 с, до 20 одновременно); http-записи проверяются напрямую; если конфиг ломает запуск, группа делится и проверяется по одной.
- `connect`: probe_all, затем берёт самую быструю (пинг) рабочую (записи с недавней ошибкой шлюза идут позже: штраф 180 с), запускает основной Xray и перепроверяет; если ни одна не работает, возвращает None и `BotRunner` подключается **напрямую** (`direct_fallback`, в панели красная плашка «proxy_failed»).
- `watch`: каждые 20 с проверяет активный; 2 промаха подряд или смерть процесса означают, что прокси мёртв; пинг выше 1000 мс (не чаще раза в 5 минут) запускает полную проверку, и если есть более быстрый, возвращается сигнал к переподключению; иначе остаётся самый быстрый.
- `maintain` (задача в `__main__`): раз в 10 минут `probe_all` по всем записям (включая неиспользуемые, статус «не работает» может стать «работает») и `cleanup`: запись, не отвечающая дольше **суток**, удаляется (активная не удаляется).
- `validate_token`, `capture_images`, загрузка аватарок идут через `state.proxy_url`.

## 10. Пасхалка kos (в README не упоминать)

Если фокус не в поле ввода, набор клавиш K, O, S подряд (по физическим кодам, работает и в русской раскладке, интервал до 2 с, без Ctrl/Alt/Meta) включает/выключает тему K.O.S: акцент `#8000ff`, hover `#6600cc`, выделенный пункт красный `#ff2d2d`, полупрозрачные панели, фон слегка размыт (blur 2px) и затемнён (brightness .5). Состояние в localStorage (`mb_kos`). Фон: клиент делает HEAD `/api/kos-bg`; сервер при первой активации скачивает картинку по ссылке VK из CSS-темы пользователя (`theme.py`, `sun1-13.userapi.com`), проверяет сигнатуру, сохраняет `data/kos-bg.*` и дальше отдаёт локальную копию; пока тему не включали, файла нет; если файл удалить, скачается снова; при неудаче (не чаще раза в минуту) клиент берёт ссылку VK напрямую. Источник темы: `K.O.S V2New.css` (bbnzbb, канал https://t.me/KOSvrchat).

## 13. Принятые решения и отклонённое

- Токен, а не вебхук. Нет форм ask_user_input.
- Консольный JS для удаления файлов в GitHub не писали: дали прямые ссылки `github.com/BigFloppa9/MrBeast-GTFO/delete/main/<файл>` и github.dev.
- Сброс пароля без привязанного аккаунта: удалить `data/auth.json`.
- Из Discord-канала логов записи не удаляются (в панели данные заменяются на null).
- Лицензия не выбрана (решает владелец).
- Пауза = бот перестаёт реагировать на спам, но остаётся в сети; ручные команды работают (это решение Брони, не обсуждалось: при замечаниях менять).
- Порядок записей прокси больше не важен: выбор по пингу.

## 16. Версия 2.5.0: что сделано и важные детали

Прокси (2.4.0 и 2.5.0):
- Вкладка «Прокси» между «Серверы» и «Настройки»; одно поле для ссылок, конфигов и подписок; лимит 1000 записей (проверка пачками по 60 в одном процессе Xray); порог переключения по пингу 3000 мс (SLOW_MS).
- Подписки: `load_subscription` пробует User-Agent по очереди (Happ, v2rayN, браузер, curl), для Happ добавляет x-hwid (хранится в config.json) и заголовки устройства; HTML и пустой ответ дают `sub_html`/`sub_empty`; потолок 4 МБ, тело base64 до трёх слоёв, список ссылок, JSON.
- Схемы: vless, vmess, trojan, ss (SIP002 и старый вид), socks5, http; обёртки happ://add, v2raytun://, hiddify://, clash://, sing-box:// и др.; tg://socks принимается как socks5; tg://proxy и tg://mtproto дают `mtproto_unsupported` (MTProto не переносит трафик Discord).
- Конфиги sing-box (`outbounds` с полем `type`) конвертируются в Xray (`from_singbox`); несколько конфигов подряд и смешанный текст разбирает `scan_items`; префиксы вида `[09.10.2026 11:42:AM] Имя:` из копипасты чата вырезаются.
- happ://crypt5 расшифровывается локально (`happ_crypt.py`, проверено на тестовом векторе из cylaro/happ-decrypt). Ключи (36 штук) скачиваются из этого репозитория по закреплённому коммиту в data/cache/happ-crypt5-keys.json и в проект не встроены; ошибки: crypt_failed, crypt_keys_unavailable, crypt_unknown_key, crypt_unsupported (старые crypt, crypt2-4). Расшифрованный URL сохраняется как адрес подписки.
- Редактор записи (карандаш) и форма добавления: `GET/PUT /api/proxy/{id}`, `POST /api/proxy/form`; виды: socks5, http, vless, vmess, trojan, shadowsocks, JSON (Xray). Тип socks5 и http взаимозаменяемы при правке.
- Сеть: `internet_up()`; сбои не пишутся, пока интернета нет; `down` копится только при проверках с интернетом (не больше 1800 с за раз), удаление при 86400; фоновая проверка каждые 10 минут только неработающих/неизвестных записей (полная проверка при сбое активной); `wait_recovery` (раз в 90 с) возвращает бота с прямого подключения на прокси; `maintain` защищён от падений.

Бот и данные:
- Лестница наказаний: `config.steps_for`, `step_reason`, пресеты default / ladder (5 мин+60 мин; 1 д+1 д; 7 д+1 д; бан+1 д) / ladder_ban (одно действие: бан + удаление за сутки; по ответу пользователя, не вариант лестницы) / custom (до 8 шагов, сохраняются в настройках сервера). Счётчик в `strikes.json` (по серверу и пользователю), сброс через `warn_reset_days` (по умолчанию 30, максимум 90), фиксируется только после успешного действия. Раньше `processed_users` блокировал повторные срабатывания навсегда; теперь `busy` + кулдаун 60 с.
- Причина: может уходить нарушителю в ЛС (`dm_notify`, с 2.5.1 по умолчанию ВЫКЛЮЧЕНО; для бана ДО бана, для таймаута после) и в журнал аудита (обрезается до 512). Подсказка в панели переписана соответственно.
- Лог-запись теперь содержит `action`, `strike`, `discord` (канал и сообщение). Удаление данных (`api_erase`) стирает записи, счётчики, строки консоли и сообщения бота в лог-каналах: по сохранённым ссылкам и просмотром истории (3000 сообщений за 90 дней, только сообщения самого бота, где в эмбеде встречается ID).
- Несколько модераторов (`moderators`, до 10; `/reg` добавляет, `/log` доступна всем привязанным, `DELETE /api/moderator/{id}`); старое поле moderator_id мигрирует.
- Сброс пароля: до 3 контрольных вопросов (ответы нормализуются, только латиница/цифры/_.-, PBKDF2-хеш 200000 итераций), подсказка (показывается после 2 неверных входов, поле пароля очищается), `/api/forgot/answers`, при отсутствии способов страница показывает команду переустановки (`reinstall_info`: Termux определяется по TERMUX_VERSION).
- Экспорт/импорт: `/api/data/export|import`; настройки серверов открыто, счётчики в Fernet-блоке с ключом из парольной фразы (PBKDF2 200000); логи и нарушители не входят; импорт отбрасывает записи старше срока и валидирует настройки (`sanitize_settings`).
- Консольный лог (с 2.5.1 отдельная вкладка «Логи» между «Прокси» и «Настройки», на всю страницу, 300 строк): `/api/console` и `/api/console/export` (txt/json/csv, всё или с последнего запуска бота); `console.mark_activation()` вызывается в `BotRunner.start`.
